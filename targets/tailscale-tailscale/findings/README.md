Wave 2 (tka + types/key): 14 new properties (40 total), all passing at

| # | Finding | Verdict |
|---|---------|---------|
| 001 | Filter model mismatch when the harness passed `localNets=nil` (every inbound packet dropped as "destination not allowed" before rules were consulted) | harness artifact — fixed harness-side, no upstream bug |
| 002 | T4 "untrusted key" was secretly trusted: the harness derived it with key index 0 under a second salt, and when rapid shrank both salts to 0 it collided bit-for-bit with the genesis signer, so `Inform` correctly accepted it | harness artifact — fixed harness-side (untrusted key now derived with index 77), no upstream bug |

No confirmed upstream bugs were found in either wave. One code smell
noticed by reading in wave 1 (not a counterexample): the family-mismatch
guard in `wgengine/filter.Filter.Check` contains a never-true clause
`(srcIP.Is6() && srcIP.Is4())`; the observable contract (mismatched
families are dropped) still holds via downstream checks. See the Notes
section of `../PROPERTIES.md`.
